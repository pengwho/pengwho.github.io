有在看台股的人都知道，**公開資訊觀測站的重大訊息**是第一手資訊：增資、發可轉債、取得資產、子公司投資，都會在這裡公告。

問題是，每天幾百則。我只在意其中幾家公司的幾種公告，但要一則一則看實在太累。

所以我在設計一個 Agent，幫我做這件事。

## 它要做的事

1. **定時抓**：每隔一段時間抓一次最新的重大訊息
2. **過濾**：只留下我追蹤的公司
3. **讀懂**：用 LLM 讀公告內容，判斷是哪一類、重不重要
4. **通知**：重要的推到 LINE，順便附上一句白話摘要
5. **留存**：全部存進資料庫，之後可以回頭查

## 技術選擇

| 環節 | 工具 | 為什麼 |
|---|---|---|
| 排程 | cron | 最簡單，不會壞 |
| 儲存 | SQLite | 一個檔案，好備份 |
| 理解內容 | LLM | 公告寫法五花八門，規則寫不完 |
| 通知 | LINE Bot | 每天都會打開 |
| 歷史紀錄 | GitHub Pages | 免費的靜態網頁，隨時可以查 |

## LLM 要做什麼、不做什麼

這是設計時最重要的決定。

**要做的**：分類（增資、可轉債、財報、人事異動……）、摘要成一兩句白話、標出重要程度。

**不做的**：給買賣建議。這個 Agent 的工作是幫我省下看公告的時間，判斷還是我自己來。

## 怎麼知道它分對了

我會先手動標一批公告的正確分類，當作考卷。每次改 prompt 或換模型，就重新考一次，看準確率有沒有變好。沒有這份考卷，就只能靠感覺，而感覺通常是錯的。

做好之後，它也會變成作品掛板上的一員。
